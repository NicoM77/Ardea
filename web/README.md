# Ardea web

Angular 22 workspace: the application `ardea` (`projects/ardea`) and the component library `ui`
(`projects/ui`). Standalone components, signals, zoneless change detection, OnPush (the Angular 22
default), strict TypeScript. Rules: master plan chapters 2.4, 11 and 13.4; the look: `../DESIGN.md`.

Requirements: Node 24 (`fnm use 24`).

```bash
npm ci
npm start                # dev server on http://localhost:4200, /api proxied to http://localhost:5080
npm test                 # Vitest unit tests (ui and ardea)
npm run lint             # ESLint with angular-eslint, template accessibility rules included
npm run check:i18n       # every key used in code is in en.json, and every key in en.json is used
npm run check:tokens     # no colour values outside projects/ui/src/styles/tokens.css
npm run check:licenses   # production packages against ../build/licenses/allowed-licenses.json
npm run build            # production build into dist/ardea/browser (base href "/", hashed files)
npm run generate:api     # regenerate the API client from ../openapi/ardea.v1.json (CI checks it matches)
```

## Layout

| Where | What |
|---|---|
| `projects/ui/src/styles/` | `tokens.css` (the only place with colour values), base, controls, overlay, motion, fonts |
| `projects/ui/src/lib/` | the components; each has its states (default, hover, focus, disabled, loading, error, empty) |
| `projects/ardea/src/app/core/` | API client (`api/client.ts`, generated by orval into `api/generated/`), session and guards, HTTP interceptors, translations |
| `projects/ardea/src/app/layout/` | the signed-in shell (sidebar, top bar, search) and the sign-in frame |
| `projects/ardea/src/app/features/` | pages: sign-in area, account, administration, placeholder areas |
| `projects/ardea/src/app/showcase/` | the component library pages at `/ui`, development builds only |
| `projects/ardea/src/i18n/en.json` | English, built in; other languages load from `/i18n/<lang>.json` |
| `e2e/` | Playwright: visual comparison of the `/ui` pages (baselines in `e2e/baselines/`) and the production build under the production CSP |

The API client is generated by orval (`orval.config.ts`): reads as `httpResource` helpers, writes
as `HttpClient` services. Never edit `core/api/generated/`; change the API, commit the new
`openapi/ardea.v1.json`, run `npm run generate:api` and commit the result. CI fails when they differ.

## Playwright: visual comparison and CSP

Both projects serve a build with `scripts/serve-static.mjs`, which sends the Content Security
Policy the API sends in production (read from `src/Hosts/Ardea.Host/Http/RequestProtection.cs`),
and both fail on any console error.

- `visual`: one image per component library page, in Chromium on Linux, against a development build
  in `dist/showcase` (the production build leaves `/ui` out). CI runs it on pushes to `main` only
  (master plan 13.7).
- `csp`: the production build in `dist/ardea` loads its pages under the policy. CI runs it on every
  pull request. It is what keeps `eval` and inline script out of the app.

Build on the host, then run in the official Playwright image so the images match CI. The whole
repository is mounted, because the server reads the policy from the host's source:

```bash
npx ng build ardea
npx ng build ardea --configuration development --output-path dist/showcase
docker run --rm --ipc=host --user "$(id -u):$(id -g)" -e HOME=/tmp -e CI=true \
  -v "$PWD/..":/repo -w /repo/web mcr.microsoft.com/playwright:v1.56.1-noble npx playwright test
```

After an intended visual change, add `--project visual --update-snapshots=all` and commit the new
images. The comparison is strict (near-grey palette), so review the diff images in `test-results/`
before accepting.

## Licence exceptions

`license-exceptions.json` names each production package whose licence is not on the allow-list,
with the reason it is accepted. The check fails on any other package and on a stale entry.
